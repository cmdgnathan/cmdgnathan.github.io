Squirrel turret

Placeholder. Posting the clips first — the real write-up (calibration procedure, detector training, the failure modes) is still to come.

The squirrels dig up the mulch bed. So: a pan/tilt water turret that watches the yard, decides whether the thing moving out there is a squirrel, and points a hose at it.

The build splits cleanly into two halves that turned out to be almost independent problems. Detection — given a camera frame, is there a squirrel in it, and where? — runs on a Raspberry Pi off a fixed camera's infrared stream: a cheap motion gate proposes regions, and a small trained image classifier decides whether each crop is actually a squirrel. Aiming — given a target location in the image, where do the servos need to point? — is the part that had a nice shortcut.

The aiming shortcut

The obvious approach is to solve it properly: recover depth from the camera, work out the camera-to-turret transform, then model the water's trajectory to get pump pressure sag and droplet drag right. Three hard calibrations, each with its own failure modes, multiplied together.

But the camera never moves. Which means a pixel already encodes a ground location — so the whole chain collapses into a single empirical lookup table: pixel → pan/tilt servo command. You walk a grid of image cells, jog the turret until the water lands in each one, and record the command. The table is the calibration. No depth in the runtime path, no camera-to-turret geometry, no ballistics model — the pressure sag and the drag are just baked into the numbers you recorded.

The catch is that the table is only valid for the ground plane it was calibrated against, so detection has to aim at the target's feet rather than its centroid. A separate geometric solve still exists as a fallback and as an independent sanity check that the table's numbers are physically plausible.

Safety

Two independent layers, on purpose. Software pan/tilt limits are enforced on every aim command, set so the turret physically cannot point at the house or the street. And the fire path refuses to trigger unless a hardware dead-man switch is active. Neither one is allowed to be the only thing standing between a bug and a hose pointed somewhere it shouldn't be.

Still open

  • Detection and aiming are separate codebases and aren't fully integrated yet.
  • The classifier needs far more real yard footage — birds and shadows are the interesting false positives.
  • Splash detection to auto-correct the lookup table, so recalibration stops being a manual grid walk.
  • Leading a moving target, rather than firing where it currently is.
